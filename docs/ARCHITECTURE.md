# 架构

```text
内容/媒体
   │
   ▼
PublishJob ──► SQLite 队列 ──► 人工审批
                                  │
                                  ▼
                           RiskGuard 风险检查
                                  │
                    ┌─────────────┴─────────────┐
                    ▼                           ▼
          social-auto-upload CLI       xianyu-auto-reply API
          抖音 / 小红书                 闲鱼商品发布
                    │                           │
                    └─────────────┬─────────────┘
                                  ▼
                     回执 / 失败 / 挑战锁定
```

## 设计原则

1. 编排器不保存浏览器 Cookie，由各上游发布器维护自己的登录态。
2. 平台适配器只返回规范化结果，不直接修改任务数据库。
3. Worker 通过 SQLite 原子状态变更领取任务，避免同一个任务并发发布。
4. 挑战检测优先失败关闭：一旦出现验证码或风险验证，锁定平台＋账号。
5. 所有真实发布都需要配置和命令行两道开关。
6. 上游通过 CLI 或 localhost HTTP 边界调用，避免直接复制受不同许可证约束的源码。

## 状态机

```text
waiting_approval → pending → running → succeeded
                              ├──────→ failed
                              └──────→ blocked → 人工处理
```

发布进入 `running` 后如果进程异常退出，不能自动恢复为 `pending`。这是刻意设计：外部平台可能已经收到发布请求，自动重试会造成重复内容。
