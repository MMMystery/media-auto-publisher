# 官方 API 策略

## 原则

只要账号和应用具备官方投稿权限，就应优先走官方 API/SDK。浏览器自动化仅作为没有适合公开能力时的后端，并且必须保留人工接管。

## 抖音

抖音开放平台提供投稿能力，但需要创建网站或移动应用、申请权限并通过审核。部分场景会拉起抖音编辑/发布页，需要用户最终确认，因此不能假设它等同于服务器后台静默发布。

接入计划：

1. 创建抖音开放平台应用并申请“投稿能力”。
2. OAuth 授权只申请发布所需最小 scope。
3. token 加密存储，不写 TOML、日志或任务数据库。
4. 为账号配置 `official_api` 后端；如果 token 或权限不可用，默认失败，不自动切回浏览器。
5. 只有账号显式允许时，才可人工选择浏览器兜底。

## 小红书与闲鱼

目前项目不假设存在面向普通个人创作者的通用公开发布 API。若账号后续取得平台官方服务商或商家接口权限，应新增独立适配器，而不是把官方 token 塞进现有浏览器适配器。

## 为什么不自动降级

官方 API 失败可能意味着权限收回、内容被拒或账号状态异常。此时自动改走浏览器，会掩盖真实原因并增加重复发布风险，所以必须人工确认后才能切换后端。
